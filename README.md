# RoboStux Status

> Uptime monitor and status page for RoboStux's services, powered by [GitHup](https://github.com/StuxGroup/GitHup).

[**Visit the status page →**](https://status.robo.st)

GitHub Actions checks every service regularly. The workflow asks GitHub for a run every 5 minutes, but GitHub runs scheduled workflows best-effort, often far less often, so the status page shows the real check rhythm. When a run is late, it checks up to 4 times, 5 minutes apart, to fill the gap. Results are stored as JSON in
[`data/`](data), outages open an [Issue](https://github.com/RoboStux/Status/issues) that is
closed again on recovery, and the status page is published to GitHub Pages at
[status.robo.st](https://status.robo.st). Its legal pages (the `legal:` block in
[`.githup.yml`](.githup.yml)), 404 page and sitemap are generated by GitHup, and the footer shows
GitHup's version, linking to [GitHup's changelog](https://githup.stux.group/changelogs/#githup).

| Group | Monitor                | URL                                     | Checks                                                                                                  |
| ----- | ---------------------- | --------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Web   | RoboStux Website       | `https://robo.st`                       | The public website                                                                                      |
| Web   | RoboStux CDN           | `https://global.media.robo.st/logo.png` | The media CDN                                                                                           |

| Web   | RoboStux GitHub Pages  | `https://robostux.github.io`            | The redirect to the GitHub organisation (a meta-refresh page that answers 200)                          |
| Bot   | RoboStux Shard 1       | `https://shard1.robo.st/health/all`     | Every platform: 200 when every live one is connected and ready (Discord; Fluxer and Twitch coming soon) |
| Bot   | RoboStux for Discord   | `https://shard1.robo.st/health/discord` | The Discord bot: 200 when it's connected and ready, 503 otherwise                                       |

Every monitor counts any 200-399 answer as up, except RoboStux Shard 1 and RoboStux for Discord, where only a 200 counts. Answers
slower than 15 seconds show as degraded. Monitors are configured in [`.githup.yml`](.githup.yml),
in two groups that the status page shows as sections, each with a combined status.

## How it's published

`.github/workflows/githup.yml` builds the status page into `_site` with GitHup (legal pages, 404 and sitemap included) and
deploys it with `actions/deploy-pages`, so the repository's **Settings → Pages →
Source** must be **GitHub Actions**, with `status.robo.st` as the custom domain.

The page's logo and favicons are its own badge icon (the RoboStux mark with a heartbeat badge), kept in
[`icons/`](icons) and published at the site root. [`scripts/badge-icons.py`](scripts/badge-icons.py) builds
them; see [CONTRIBUTING.md](CONTRIBUTING.md#the-icon). Preview it all
locally with `./dev-server.sh --demo` (or `dev-server.bat --demo`).

## Versioning

This project uses [Date Versioning](https://datevers.ing): each release is numbered by its UTC release date as `YY.MM.DD` (for example `26.10.23`), with `-1`, `-2`… for later releases the same day. See [CHANGELOG.md](CHANGELOG.md) for what changed in each release.

Releases are made on the `test` branch and go live when its pull request into `main` is merged; see [CONTRIBUTING.md](CONTRIBUTING.md#branches).
